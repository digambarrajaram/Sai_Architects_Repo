Issue 1 — Stat cards are still excessively tall with massive empty space
The Pending (yellow), Approved (green), and Rejected (pink) stat cards remain 
very tall vertical columns (~250–300px) with only an icon + label + number at 
the very top and a huge empty colored area below. The Total, Count, and Average 
cards beside them are compact and flat by contrast, creating severe visual 
imbalance.

Fix: Cap the height of ALL stat cards uniformly. Set:
  .stat-card { max-height: 96px; min-height: 72px; }
The Pending/Approved/Rejected cards should NOT stretch to fill vertical space. 
Use align-items: flex-start on their container, not stretch.

Issue 2 — Large blank gap between stat cards row and the expense list
Between the stat cards section and the "Showing X expenses" / expense list below, 
there is an enormous empty white area (~200px of blank space). This makes the page 
feel broken — as if content failed to load.

Fix: Remove any fixed min-height or padding on the container between the stat 
cards and the list. The expense list should sit directly below the stat cards 
with normal spacing (16–24px gap max). Check for any wrapper div with a hardcoded 
height or padding-bottom causing this gap.

Issue 3 — "Active Filters" section appears AND disappears inconsistently
When a filter is applied (e.g., "This Month"), the "Active Filters:" chip appears 
below the stat cards. But when the filter panel is opened and a different date 
range ("All Time") is selected, the Active Filters section disappears entirely 
even though a filter is still active. Then when "Custom Date Range" is used with 
a Status filter, two chips appear ("Custom Date Range ×" and "Status: Pending ×").

The behavior is inconsistent — the "Active Filters" row should always be visible 
when ANY non-default filter is active, and hidden only when all filters are reset 
to defaults.

Fix: Show the "Active Filters:" section whenever at least one of these is true:
  - dateRange !== 'thisMonth' (or whatever the default is)
  - selectedCategories.length > 0
  - minAmount !== '' || maxAmount !== ''
  - statusFilter !== 'all'
  - searchQuery !== ''

Issue 4 — Filter panel has no visible header/title or close affordance
When the filter options panel opens (Date Range, Categories, Amount Range, Status, 
Sort By), it appears inline on the page with no clear heading or way to collapse 
it. There's also no "Apply Filters" button visible until the user scrolls down.

Fix: Add a collapsible filter panel with a clear "Filters" heading and 
collapse/expand toggle (chevron icon). The "Apply Filters" button should be 
sticky at the bottom of the panel:
  position: sticky; bottom: 0; background: white; padding: 12px;

Issue 5 — "Custom Date Range" modal has greyed-out "Apply Date Range" button 
even before selecting dates
The "Select Date Range" bottom sheet modal shows Start Date and End Date fields, 
but the "Apply Date Range" button is already greyed out (disabled) before the 
user has even tried to submit with empty fields. The visual state doesn't 
communicate WHY it's disabled.

Fix: Keep the button muted/disabled until BOTH Start Date and End Date are 
filled in. But also show a small helper text when the button is disabled:
  <p className="text-xs text-gray-400 text-center mt-1">
    Select both start and end dates to continue
  </p>

Issue 6 — Expense list items show description text directly on the card without 
truncation
The "Labor" expense item shows its full description "This the expense. This also 
not is db schema • 20 Feb 2026" inline on the card. Long descriptions overflow 
the card layout and push other content.

    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
    max-width: 60%;
  }

Issue 7 — "Expense Title" field value is NOT displayed on the expense list card
The Add Expense form now has an "Expense Title (Optional)" field, but after saving, 
the expense list card shows only the Category name ("Labor", "Materials") as the 
title — NOT the custom Expense Title entered by the user.

Fix: On the expense card, show the Expense Title if it was provided, falling 
back to the Category name only if Expense Title is empty:
  const displayName = expense.title || expense.category;
  
Also, note: the user typed "title. this is not in DB schema" as the expense 
title — confirming that the "Expense Title" field value is not being saved to 
the database. Ensure the `title` field is included in the INSERT/UPDATE payload

  }
